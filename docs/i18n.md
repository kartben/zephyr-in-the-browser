# Translating Zephyr in the Browser

The page speaks English and French today. Adding a language takes one JSON
file, and the guided tours translate as ordinary Markdown. Nothing needs
registering: a language exists when its file does, the same way a tour is just
a file in `tours/`.

| What | Where | Format |
| --- | --- | --- |
| The page's strings | `src/locales/<code>.json` | [i18next JSON](https://www.i18next.com/misc/json-format) |
| A guided tour | `tours/<code>/<tour id>.tour.md` | The [tour format](tours.md), prose translated |

`<code>` is a BCP 47 language tag, the way browsers and translation platforms
spell it: `fr`, `de`, `ja`, `pt-BR`, `zh-Hans`.

## How the page picks a language

Highest first:

1. `?lang=fr` in the address, for a link that should open in French (a
   workshop handout, a slide). It applies to that visit and is not remembered.
2. The language picked under **Settings → Language**, saved in the browser.
3. The browser's preferred languages, in order. `fr-CA` reads `fr`; `pt`
   reads `pt-BR` when that is the only Portuguese.
4. English.

Picking a language reloads the page, which restarts the guest. Any string or
tour a language has not translated yet shows in English.

## Adding a language

1. Copy `src/locales/en.json` to `src/locales/<code>.json`.
2. Translate the values, never the keys. Keep these as they are:
   - `{{placeholders}}`, which the page fills in: `"Start at stop {{step}}"`.
   - `<tags>`, which become links, code or key badges: `"Press <help/> or <alt/> …"`.
3. Give each plural every form your language needs. English has two,
   `stops_one` and `stops_other`; French needs `_one`, `_many` and `_other`,
   Polish `_one`, `_few`, `_many` and `_other`. `npm test` names any form you
   are missing, because i18next quietly falls back to English for it.
4. Run the checks:

   ```console
   npm test                    # catches stray keys, lost placeholders and tags, missing plural forms
   npm run i18n:status <code>  # what is left to translate
   ```

5. Open the page with `?lang=<code>` (`npm run dev`, then
   <http://localhost:5173/?lang=de>) and look around. **Settings → Language**
   lists the new language under its own name (Deutsch, 日本語), which the
   browser supplies.

You do not have to translate everything at once. Leave out a key, or leave it
empty, and that string shows in English.

### With a translation platform

The locale files are i18next JSON (v4), which Weblate, Crowdin, Lokalise,
Tolgee and the i18n Ally editor extension read and write as they are. On
Weblate, that is the *i18next JSON file v4* format, file mask
`src/locales/*.json`, monolingual base file `src/locales/en.json`.

## Translating a tour

A translated tour runs in place of the English one, step for step. So it has
to stop where the English one stops and read what it reads: only the words
change.

1. Copy `tours/<tour id>.tour.md` to `tours/<code>/<tour id>.tour.md`. The
   language needs a `src/locales/<code>.json` too.
2. Translate:
   - the `tour:` title in the front matter,
   - the introduction, every `##` heading and its prose,
   - in a ```` ```tour ```` block, only the lines a reader sees: `await:`,
     `pass:`, `fail:`, a `memory:` block's `note:`, and a `watch:` row's label
     (the part before `=`, as in `broche = led+1p as u8`).
3. Leave everything else exactly as it is: `sample:`, `source:`, `sources:` and
   `next:` in the front matter, every other line in the ```` ```tour ````
   blocks (`at:`, `when:`, `look:`, `check:`, `do:` and the rest), shell
   commands, and the `{watch}`-style lines that place a view in the prose
   (move them within a step if your sentence order needs it, but keep them).
4. When the prose names something on the page, use your locale file's word
   for it. The French Blinky tour says **Continuer**, because that is what
   its button says.
5. Run `npm test`. A translation that does not line up fails with the step
   and the directive that differ, such as
   ``step 2 (Watch the LED in the device dock): `at:` differs``.

`tours/fr/blinky.tour.md` is the worked example: diff it against
`tours/blinky.tour.md` to see what changes and what does not.

Because the steps line up one for one, a `?step=3` link, the step outline and
the gallery's tour list mean the same in every language. Where a tour has no
translation, the gallery lists its English title and it runs in English.

### When an English tour changes

If you change where a tour stops or what it reads (a ```` ```tour ```` block,
a step added or removed, the front matter), make the same change in each of
its translations; `npm test` lists the ones that no longer line up. You do not
have to translate a new step yourself: copy it in English, and a translator
can pick it up. If a translation slips through out of step anyway, the page
runs the English tour and says why in the console.

## Adding strings to the page

For anyone changing the UI:

- Put the English in `src/locales/en.json`, grouped by the part of the page
  it is on, and read it with `useTranslation()`:

  ```tsx
  const { t } = useTranslation()
  return <Button title={t('topBar.restartTitle')}>{t('topBar.restart')}</Button>
  ```

  Outside React, use `i18n.t()` from `@/i18n` (see `noTraceNote` in
  `src/tours/look.ts`).
- Keys are typed from `en.json`, so a misspelt key fails `npm run typecheck`.
- Values: `t('gallery.description', { board: board.label })` fills
  `{{board}}`.
- Plurals: write `key_one` and `key_other` in `en.json`, and pass `count`:
  `t('tour.intro.stops', { count: steps.length })`.
- Markup inside a sentence: `<Trans i18nKey="…" components={{ code: <code /> }} />`
  with `"Set by <code>?bridge=</code>."` in the JSON, so translators can move
  the tag with the words.
- Write whole sentences. `"In this tour, {{count}} stops"` translates;
  `"In this tour, " + count + " " + noun` does not.
- Leave the other locale files alone: a new key shows in English until a
  translator gets to it, and `npm run i18n:status` lists it for them.

## Not translated yet

The top bar, Settings, the app picker, Help, the device dock's frame and the
tour cards are translated. These still show in English and are good first
contributions, extracted the same way:

- the device rows themselves (sensor cards, GPIO, network, I²C, SPI and the
  rest) and the gallery's device tags,
- the Trace and Debug instruments,
- the changelog, which is written once, in English.

Sample names and descriptions come from the Zephyr documentation and stay as
Zephyr writes them.
