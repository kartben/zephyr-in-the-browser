CPU power states — Trace Timeline density study

From real styles: every token below is copied verbatim from src/index.css, and the thread-lane colours from src/ctf/types.ts STATE_COLOR. Geometry is 1:1 CSS pixels against the real constants — LABEL_W 128, AXIS_H 28, SECTION_HEADER_H 15, SECTION_GAP 4, lane heights 16/22/40. The one question this page exists to answer: does a 16 px CPU row read instantly without dominating a panel that already carries six thread colours?

The ramp against everything already on this canvas

Why one hue and not seven colours. pm_state is ordinal (0 active → 6 soft-off), so a sequential ramp is the correct encoding and a categorical palette would be actively wrong — seven unrelated hues cannot be ordered by eye, and there are only about three unclaimed hues left on this canvas anyway. Borrowing the slp cyan neighbourhood means a reader who already knows “cyan = sleeping” gets the CPU row for free: it is less to learn, not more. The one genuine near-miss is queue-depth sky at hue 235, mitigated by 25° of hue and by the two sections never being adjacent.

CPU 1.5% · slept 98.5% · ctxsw 61 (3/s) · window 18.149s

This is the dense extreme, not the typical case. The data is the real pm_latency trace measured in this branch — 16 segments over 18.1 s, 98.5 % slept, deepest standby — so the row is nearly solid on purpose: a power-management demo sleeps almost all the time. An ordinary application inverts this and the row is mostly trough, because every gap is PM_STATE_ACTIVE and ACTIVE draws nothing, ever. Variant D shows the floor.

What the mockup changed about the design. A first pass put the shallow end of the ramp at oklch(0.55 0.04 215 / 0.55) and it was a mistake: against the rgba(15,23,42,0.45) trough a lane reveals, runtime-idle was nearly indistinguishable from awake — the one distinction the row exists to make. The ramp now starts brighter and more chromatic, so even the shallowest state clearly reads as “something”, and the ordering still carries depth. Worth recording because the temptation is to keep the shallow end quiet: quiet is right for the legend, wrong for the floor of the ramp.

The latency story reads without any text. Compare the middle stretch, where a 10 ms constraint makes standby unreachable: the deep band simply stops appearing. That absence is the finding.

Why above THREADS rather than below QUEUES. Top-to-bottom becomes substrate → actors → objects, which is a real gradient. But the decisive reason is positional stability: visibleLanes() grows as threads are created during boot, so a row below the threads slides downward while you are watching it in a live 500 ms-repaint view. Above them it is pinned at a constant y. Note also that the idle thread lane and the CPU band say almost the same thing here — which is exactly why the band is not derived from thread names: a heuristic band is indistinguishable from a measured one once painted.

B · Rejected — CPU below QUEUESrejected

Same information, worse behaviour. Every new thread pushes the row you are reading further down, and on a machine that creates threads during boot that happens repeatedly in the first seconds — precisely when someone is watching. Flipping this is one array position in timelineGeom() if the ordering argument loses.

C · Worst case — two CPUs, Default 22 px, dense declines

The stress case. A guest whose policy declines constantly makes the notch strip near-continuous. It stays a 2 px baseline detail rather than competing with the fill, and it is pixel-thinned exactly like MSGQ_MARK_MIN_GAP_PX. If any variant on this page is going to be judged too busy, it is this one — and the escape hatch is already designed: the whole section is behind a toolbar toggle, like the queue overlay.

Names, residencies and thresholds all come from the devicetree (src/dts/powerStates.ts) — the CTF events carry only {cpu, state, substate_id}. Numbers, not grades: min-residency-us is a policy input compared against predicted idle time, so scoring achieved residency against it and printing a ✓/✗ would be a confident value judgement on an emulated clock. “early wake” is a factual phrase; the reader draws the conclusion. The budget line is the genuinely new capability: it pairs what the policy was offered with what it picked, which is how “standby was affordable and still not chosen” becomes visible at all.
